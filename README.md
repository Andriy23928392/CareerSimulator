## 1. Призначення програми та опис предметної області
**Football Career Simulator** — це консольний рольовий симулятор (CLI/TUI RPG) кар'єри професійного футболіста. Програма моделює життєвий цикл спортсмена від юнацького віку до виходу на пенсію. 

Гравець має можливість керувати розвитком персонажа, приймати рішення щодо трансферів, взаємодіяти з медіа, купувати нерухомість та витратні матеріали, а також здобувати командні (Ліга Чемпіонів, Чемпіонат Світу) та індивідуальні (Золотий м'яч) нагороди.
Головне завдання симулятора — продемонструвати баланс між витратами енергії, покращенням навичок, психологічним станом (мораль, довіра тренера) та фінансовим успіхом.

## 2. Архітектура проєкту
Проєкт побудований з використанням багатомодульної архітектури, яка чітко розділяє бізнес-логіку та інтерфейс користувача. Рішення (Solution) `FootballCareerSim.slnx` містить два основні проєкти:

1. **CareerSimulator.Domain (Бізнес-логіка)**
   - `Models/`: Опис базових сутностей (`Player`, `Club`, `PlayerStats`, `PlayerAttributes`, `PlayerUpgrades`, `Position`).
   - `Core/`: Ядро симуляції часу та розрахунків (`TimeManager`).
   - `Activities/`: Ігрові дії, реалізовані через інтерфейси (`TrainingActivity`, `MatchActivity`, `RestActivity`).
   - `Items/`: Об'єкти ігрового магазину (`Consumables`).
   - `Logic/ & Services/`: Менеджери трансферів (`TransferManager`) та генерації травм (`MedicalCenter`).
   - `Infrastructure/`: Робота з файловою системою та серіалізацією (`SaveManager`).

2. **CareerSimulator.UI (Представлення)**
   - Містить лише точку входу (`Program.cs`) та класи для рендерингу консольних меню (`StoreMenu`, `ProfileMenu`, `SocialMenu`).

Цей поділ відповідає принципам **SOLID** (особливо Single Responsibility) — UI нічого не знає про те, як саме розраховуються шанси на перемогу, а Domain не містить логіки виводу тексту в консоль (окрім спеціальних сповіщень).

## 3. Детальний опис ігрових механік

### 3.1. Генерація та характеристики гравця
Персонаж (`Player`) має унікальний набір характеристик, які залежать від обраної позиції (Goalkeeper, Defender, Midfielder, Forward). Навички (Pace, Shooting, Passing, Defending тощо) зберігаються у класі `PlayerAttributes`. Загальний рейтинг (OVR) розраховується динамічно за допомогою вагових коефіцієнтів, унікальних для кожної позиції. Після досягнення 32 років включається механіка старіння: фізичні показники поступово знижуються.

### 3.2. Симуляція матчів
Матчі (`MatchActivity`) генеруються з урахуванням багатьох факторів:
- **Тип поля:** Домашній матч дає бонус до перемоги, виїзний — штраф та підвищує витрату енергії.
- **Мораль:** Депресія гравця (мораль < 30) збільшує витрату енергії на 50%, тоді як кураж (мораль > 80) збільшує шанси на перемогу.
- **Події:** Вбудована система генерації мікроподій (наприклад, пробиття пенальті гравцем або відбиття удару воротарем), що вимагає вводу користувача прямо під час матчу.

### 3.3. Економіка та магазин (Поліморфізм)
Зароблені кошти можна витратити в абстрактному магазині (`StoreMenu`). П
- **Consumables :** Наприклад, протеїнові коктейлі, які можна купувати багато разів для миттєвого відновлення енергії.

### 3.4. Трансферний ринок
Реалізовано систему агентств (`TransferManager`). Гравець може покращувати рівень свого агента за гроші. Клуби розбиті на тири (Standard та Veteran для гравців 34+ років). Перехід до топ-клубу вимагає певного рівня рейтингу (OVR) та Слави (Reputation). Можливе підписання попередніх угод поза межами трансферних вікон.

### 3.5. Система трофеїв та нагород
Гра відстежує єврокубки та міжнародні турніри (Ліга Чемпіонів, Чемпіонат Світу, Ліга Націй), враховуючи 4-річні цикли. В кінці сезону розраховуються шанси на перемогу в чемпіонаті. Індивідуальна нагорода «Золотий м'яч» видається виключно за видатну статистику (наприклад, рейтинг 90+ та велика кількість голів/кліншитів).

## 4. Використання можливостей мови C# та .NET 10
Проєкт використовує широкий спектр сучасних можливостей мови C#, згідно з вимогами до курсової роботи:

1. **Generics (Узагальнення)**
   Використано класи `List<T>` для зберігання інвентарю гравця (`List<string> PurchasedItems`), історії трофеїв (`List<string> Trophies`) та каталогу магазину (`List<Item> _storeItems`). Це забезпечує типобезпеку та високу продуктивність.

2. **Обробка винятків (Exceptions)**
   Реалізовано надійну систему контролю бізнес-правил. Наприклад, спроба купити товар без грошей або виконати дію без енергії генерує `Exception` або `NotEnoughEnergyException`, який перехоплюється блоками `try-catch` у UI для виведення коректного повідомлення користувачеві без аварійного завершення програми.

3. **Делегати (Delegates & Events)**
   Для розв'язки UI та бізнес-логіки використано події на базі вбудованого делегата `Action`. Зокрема, в магазині реалізовано подію `OnItemPurchased`, на яку підписується інтерфейс для виведення сповіщень під час успішної транзакції:
   ```csharp
   public static event Action<string, decimal> OnItemPurchased;
   ```

4. **Абстракція, Спадкування та Поліморфізм**
   Магазин побудовано на основі абстрактного базового класу `Item`, від якого успадковуються конкретні товари (`ProteinShake`, `LuxuryVilla`). Перевизначення абстрактного методу `Apply(Player player)` дозволяє викликати різну логіку для різних товарів, використовуючи єдиний інтерфейс.

5. **Серіалізація даних (JSON)**
   Для збереження прогресу використовується `System.Text.Json`. Стан усіх об'єктів (включно з вкладеними об'єктами `PlayerStats` та `PlayerAttributes`) серіалізується у файл `savegame.json` за допомогою `JsonSerializer`. Під час завантаження дані десеріалізуються для відновлення стану `TimeManager` та `Player`.

## 5. Тестування (xUnit)
Бізнес-логіка проєкту покрита модульними тестами з використанням фреймворку **xUnit**. Проєкт `CareerSimulator.Tests` містить перевірки, які ізольовано тестують ключові алгоритми.

**Приклади покриття:**
- **Позитивні сценарії:** Перевірка коректного списання енергії (`SpendEnergy_ShouldDecreaseEnergy_WhenEnoughEnergy`) та збільшення максимального ліміту енергії від VIP-предметів (`LuxuryVilla_ShouldIncreaseMaxEnergy`).
- **Негативні сценарії:** Перевірка того, що неможливо використати послуги психолога, якщо мораль уже дорівнює 100% (`PsychologistSession_ShouldThrowException_WhenMoraleIsMax`).
- **Обробка помилок:** Тестування генерації винятків при спробі витратити енергію, якої немає в наявності.
- **Граничні випадки:** Перевірка того, що метод відновлення енергії ніколи не перевищує параметр `MaxEnergy`.

## 6. Інструкція зі встановлення та збирання
Оскільки проєкт використовує .NET 10, для його запуску необхідно мати встановлений .NET SDK відповідної версії.

1. **Клонування репозиторію:**
   ```bash
   git clone https://github.com/DCSS-Programming-Fundamentals-2025-2026/term-paper-Andriy23928392.git
   cd CareerSimulator
   ```
2. **Запуск Unit-тестів (Перевірка цілісності логіки):**
   ```bash
   dotnet test CareerSimulator.Tests/CareerSimulator.Tests.csproj
   ```
3. **Запуск симулятора:**
   ```bash
   dotnet run --project CareerSimulator.UI/CareerSimulator.UI.csproj
   ```

## 7. Інструкція користувача
Після запуску програми користувач має можливість:
1. Ввести ім'я та вибрати амплуа (Воротар, Захисник, Півзахисник, Нападник).
2. На головному екрані доступні варіанти дій, які обираються введенням відповідної цифри:
   - **[1] Тренування:** Підвищує характеристики, але вимагає багато енергії.
   - **[2] Відпочинок:** Повністю відновлює енергію (пропуск ігрового тижня).
   - **[3] Матч:** Головний спосіб здобувати статистику. Результат залежить від ваших характеристик та рандому.
   - **[4/5] Магазини:** Купівля покращень та відновлювальних предметів.
   - **[6] Благодійний фонд:** Можна пожертвувати гроші на благодійсність та за це отримати славу.
   - **[7] Рекламні контракти:** Якщо у гравця високий рівень слави йому можуть запропонувати рекламний контракт з пасивним доходом.
   - **[8] Профіль гравця:** Можна дізнатися статистику нашого гравця та всі його характеристики.
   - **[9] Симуляція року:** Швидкий пропуск 52 тижнів із підбиттям підсумків сезону.
   - **[10] Зберегти гру:** Прогрес буде записано у `savegame.json`.
   - **[11] Агентсво:** Можна покращити свого агента для піписання у кращі клуби також кращий агент дає бонуси до зп, також можна запросити трасфер у агента і він знайде найкращі пропозиції.
3. Уважно слідкуйте за показниками **Енергії** та **Моралі**. Низька мораль викликає "Депресію" (дії стають дорожчими), а низька енергія збільшує ризик травм.
